# kurisaba
A nullchan-kusabaX based imageboard engine with some modern features

## Установка

Если кто-то захочет развернуть курисабу у себя с нуля и поделится с нами своим опытом, например, в виде написания issue-в на github - мы будем очень рады.

### Установка на живой системе

- Развернуть LAMP или LNMP-сервер, создать необходимый конфиг для сайта, проверить, что всё открывается, опционально настроить Cloudflare, Let's Encrypt и т.п. Примеры далее будут для Debian/Ubuntu + nginx.
- Использовать PHP 7.3 или 7.4 (Dwoo не умеет работать с PHP >= 8.0) с модулями `mbstring`, `gd`, `curl`, `yaml` и с поддержкой нужной базы данных (например, MySQL) в PDO (обычно модуль `mysql`):
```
    wget https://packages.sury.org/debsuryorg-archive-keyring.deb && sudo dpkg -i debsuryorg-archive-keyring.deb && rm debsuryorg-archive-keyring.deb
    . /etc/os-release
    echo "deb [signed-by=/usr/share/keyrings/debsuryorg-archive-keyring.gpg] https://packages.sury.org/php/ ${VERSION_CODENAME} main" | sudo tee /etc/apt/sources.list.d/php.list
    sudo apt update
    sudo apt install php7.4 php7.4-fpm php7.4-mbstring php7.4-curl php7.4-yaml php7.4-gd php7.4-mysql
```
- Поставить `imagemagick` и `gifsicle` (если нужна поддержка, например, анимированных превьюшек и т.п.). и `git` (чтобы работало обновление движка из админки):
```
    sudo apt install git imagemagick gifsicle mariadb-server mariadb-client-core
```
- Под пользователем веб-сервера склонировать репозиторий в нужный каталог:
```
    sudo -u www-data git clone https://github.com/kurisaba-dev/kurisaba /var/www/kurisaba
```
- Настроить главную на `front.php` в конфиге сайта, например, для nginx:
```
    index front.php;
```
- Если сервер - nginx, то сконфигурировать директивы `error_page` в конфиге сайта (обязательно с символом "=", иначе особые треды работать не будут), а также по возможности всё остальное по образцу из `.htaccess.template`:
```
    error_page 403 = /error.php?p=403;
    error_page 404 = /error.php?p=404;
    error_page 451 = /error.php?p=451;
```
- Если сервер - nginx, и предполагается использовать offload-движок (в том числе и для геоблокировок), закрыть доступ к путям, содержащим каталоги `/thumb/` и `/src/`:
```
    location ~ /thumb/ {
        deny all;
        return 403;
    }

    location ~ /src/ {
        deny all;
        return 403;
    }
```
- Возможно, потребуется прописать директивы типа `client_max_body_size` для nginx или аналогичную для apache.
- Создать базу данных с любым названием (если ещё не создана), а также пользователя, который имеет полный доступ к этой базе, например (здесь нужно заменить `some_password` на свой пароль):
```
    sudo mysql -e 'CREATE DATABASE `kurisaba`; CREATE USER `kurisaba`@`localhost` IDENTIFIED BY "some_password"; GRANT ALL PRIVILEGES ON `kurisaba`.* TO `kurisaba`@`localhost`;'
```
- Если производится импорт с другой инсталляции курисабы, то импортировать в неё дамп содержимого старой базы, а каталоги досок положить в корень движка (или в отдельный каталог, указав его в конфиге как `KU_STORAGEDIR`; об этом ниже).
- Открыть любую страницу борды, вписать туда настройки базы данных и нажать "Submit".
- После этого движок проинициализирует себя и откроет админку (`http://example.com/manage.php`, пользователь `admin`, пароль `admin` - разумеется, надо немедленно сменить!) Можно начинать создавать секции (по умолчанию определена секция "борды") и доски на них.

Опционально можно поменять главную в соответствии с тематикой борды:

- либо положив её под именем `front.php` в корневой каталог движка;
- либо положить как есть и поправить `KU_MAINPAGE` в настройках движка в админке, если она называется иначе.
- если это статический HTML, то лучше класть не в корень, а в каталог `static`, и соответствующим образом установить `KU_MAINPAGE` (например, `static/boardface.html`).
- все другие статические ресурсы (HTML, CSS, картинки) тоже желательно класть в каталог `static`.

Для примера, главная Курисача есть в отдельном [репозитории](https://github.com/makise-homura/kurisach-resources).

Также можно положить фавиконку (`favicon.ico`) в каталог `static/images` в корне движка.

### Docker

Для развёртывания курисабы в докере нужно сделать следующее:

- Скопировать `.env-dist` в `.env`.
- Отредактировать его, поменяв `MARIADB_ROOT_PASSWORD` и `MARIADB_PASSWORD`, а также можно отредактировать другие переменные.
- Если есть, положить фавиконку в `static/images/favicon.ico`.
- Если есть, положить главную: файлы `*.php` - в корень движка; статику (картинки, CSS, HTML) - в каталог `static` (в том числе можно в подкаталоги); всё, что нужно ей на стороне сервера (например, читаемое через `file_get_contents`) - в каталог `lib/resources` (в том числе можно в подкаталоги).
- Собрать и запустить контейнер: `docker compose up --build -d`.
- Для остановки сервисов, если нужно, можно дать команду `docker compose down`.
- Если нужно также запустить phpMyAdmin, то надо стартовать (и останавливать, когда больше не нужен) профиль `development`: `docker compose --profile development up --build -d` / `docker compose --profile development down` 
- В продакшене надо будет настроить автозапуск контейнеров, а также по необходимости reverse-proxy на nginx на основной машине, обеспечивающий HTTPS.
- Дальше можно продолжать начальную настройку борды, зайдя в админку, как и в прошлом варианте.

#### Импорт данных

Если нужно не запускать борду с нуля, а импортировать данные с другой инсталляции курисабы, то надо делать так:

- Импортировать базу (проще всего через phpMyAdmin в development-профиле, но можно и руками в контейнере `db`). База сохраняется на docker volume с именем `kurisaba_db`.
- Картинки и прочие ресурсы надо положить в volume с именем `kurisaba_boards`.

## Конфиг

В конфиге на данный момент находятся параметры базы данных. Остальные настройки производятся через пункт "Engine settings" в админке.

Если производится миграция со старой версии курисабы, то необходимо:
- удалить из конфига всё, кроме того, что между строками "ЗДЕСЬ НАХОДЯТСЯ НАСТРОЙКИ, КОТОРЫЕ НАДО МЕНЯТЬ ПРИ НАЧАЛЬНОМ КОНФИГУРИРОВАНИИ БОРДЫ" и "Дальше что-то менять, скорее всего, не понадобится";
- привести некоторые параметры к современному виду, как в `config.php.template` (например, вместо драйвера, хоста и имени базы данных надо вписать туда DSN базы);
- обновить движок;
- зайти на страницу "Engine settings" в админке. Туда подгрузятся параметры из конфига, поскольку в базе их ещё нет;
- Нажать "Сохранить". В этот момент параметры будут записаны в базу;
- После этого из конфига можно удалять всё, кроме настроек базы данных - все настройки теперь будут храниться в базе. Если настройка есть и в базе, и в конфиге - то настройка из базы имеет приоритет.

Если схема каталогов отличается от стандартной для кусабоподобных движков (например, данные лежат отдельно от файлов движка), то в `config.php` можно переопределить следующие параметры:
- `$cf['KU_ENGINEDIR']`: путь в файловой системе к файлам движка. Должен быть доступен на запись веб-серверу, если предполагается обновление движка и/или начальная конфигурация. По умолчанию - тот каталог, где лежит `settings_manager.php`.
- `$cf['KU_STORAGEDIR']`: путь в файловой системе к данным (например, каталогам борд, временным файлам и т.п.). Должен быть персистентен (то есть, например, в случае контейнера - выделен в отдельный том, чтобы не терять содержимое при пересборке контейнера) и доступен на запись веб-серверу. По умолчанию - тот каталог, где лежит `settings_manager.php`.
- `$cf['KU_WEBPATH']`: часть URL, по которой веб-сервер будет отдавать динамику (`*.php`) и интерфейс (`*.css`, `*.js`, оформление, стили), то есть где находятся файлы движка. По умолчанию `$cf['KU_PROTO'] . $cf['KU_HOST']`.
- `$cf['KU_BOARDSPATH']`: часть URL, по которой веб-сервер будет отдавать статику (картинки и `*.html`), то есть где находятся файлы данных. По умолчанию `$cf['KU_PROTO'] . $cf['KU_HOST']`.

## Админка

По сравнению с обычной кусабой в админке есть специальные пункты:
- "Пересоздать статическую карту ответов". Так как карта ответов, в отличие от обычной 0chan-кусабы в курисабе статическая, то после массивных правок досок (к примеру, переноса тредов или влива дампа базы) она может сломаться, тогда следует выбрать этот пункт.
- "Сбросить лимит тредов". С целью защиты от вайпа в день можно создать не более `KU_MAXTHREADSADAY` тредов. Если нужно создать больше, то нужно выбрать этот пункт, и тогда отсчет `KU_MAXTHREADSADAY` пойдет с текущего момента, а не 24 часов до него, и можно будет создать новые `KU_MAXTHREADSADAY` тредов.
- "Специальные треды". О них ниже.
- "Подневная статистика по бордам". Позволяет увидеть, сколько сообщений было на каждой из борд за каждый день с начала существования борды. Пункт (на время генерации таблицы) сильно нагружает движок, не следует им пользоваться при большой нагрузке на сервер.
- "Posting rates". Позволяет посмотреть постинг на бордах за последний час.
- "Captcha statistics". Позволяет посмотреть, сколько капч какого языка было сгенрировано и сколько из них разгадано верно или неверно.
- "Edit special tripcodes". Позволяет создать трипкоды с заранее определённым результатом.
- "Обновить движок". Позволяет автоматически обновить кирусабу на новую версию с гитхаба.

В статистике прямо в меню показывается количество "Окаринов" (пользователей с уникальными IP, оставившими посты на борде за последний час, в том числе и удалённые) и "Агентов Организации" (тех, кто имеет активную браузерную сессию, то есть просто читает посты).
**Важно**: чтобы это работало, у процесса, от которого работает php, должно быть разрешение на `glob()` в каталоге сессий (`/var/lib/php/sessions` или подобном).
Если при этом один сервер обслуживает несколько сайтов, то чтобы сессии не мешались друг с другом, рекомендуется сессии борды класть в отдельный каталог. Например, для `nginx` это можно сделать с помощью следующей директивы в конфиге сайта:
```
    location ~ \.php$ {
        # ...
        fastcgi_param PHP_VALUE session.save_path="/var/lib/php/sessions-example.org";
    }
```

## Offload-движок

Для включения возможности блокировки постов/файлов по стране клиента, а также обратимого удаления файлов (то есть при восстановлении поста файл тоже восстанавливается) можно включить параметр `KU_OFFLOAD` в конфиге.
Если это делается на уже работающей имиджборде, то необходимо помимо включения этого параметра, зайти в каталоги `src` и `thumb` каждой доски и добавить в `.htaccess` директиву:
```
Deny from all
```

## Специальные треды

Некоторые треды могут быть доступны по коротким ссылкам и из меню.

Их можно добавить в списке тредов для меню на странице "специальные треды" админки.

Формат записи:
```
{THREAD | HIDDEN} thread-id /link/ Thread-Name
```
Здесь:
- `THREAD` - показать тред в меню и сделать возможность переходить в него по ссылке
- `HIDDEN` - не показывать тред в меню, но всё равно сделать возможность переходить в него по ссылке
- `thread-id` - id ОП-поста,
- `link` - это ссылка, по которой он будет доступен,
- `Thread-Name` - имя треда, под которым он появляется в меню.
Каждый блок записей THREAD/HIDDEN должна предварять строка вида `BOARD boardname`, где `boardname` - имя доски (без слэшей). Эта строка показывает, к какой борде относятся последующие треды.

К примеру, если там написано:
```
BOARD b
THREAD 12345 /vid/ Video Thread
```
то это означает, что в тред можно зайти как по обычной ссылке вида http://example.com/b/res/12345.html, так и по ссылке http://example.com/vid/.

Очевидно, названия имеющихся досок не должны совпадать с подобными ссылками на треды.

Если существует такой тред со ссылкой `/faq/` - то в хедере страниц борд/тредов, а также в меню появится ссылка "FAQ". Этот тред логично объявить как HIDDEN, заблокировать и спрятать, чтобы он мог быть доступен только по ссылке, но не светился на борде.
